## Featured Projects

### [6-DOF Aircraft Simulation — Modular Physics, Flight-Test Matching, Pilot-in-the-Loop](https://github.com/rohitsanjay-17-aerohub/6DOF-Aircraft-Simulation)
> *MATLAB/Simulink · Aerospace Blockset · System Identification · Real-Time Simulation*

A nonlinear 6-DOF fixed-wing simulation built as **separate, reusable Simulink physics libraries** —
aerodynamics, ISA atmosphere, propulsion, equations of motion and RC joystick input — so any single model can be
refined without touching the rest. The physics is written out from primitive Simulink blocks rather than dropped
in from canned 6-DOF or atmosphere library blocks.

Validated rather than just built: longitudinal (`Cm_q`, `Cm_alpha`, `Cm_elev`) and lateral-directional
(`Cn_r`, `Cn_beta`, `Cn_rud`) derivatives are tuned against reference flight-test data at 240 KCAS and 35,000 ft
(10,886 kg, CG at 34% MAC), using bounded `fmincon` on a normalized least-squares residual. Dutch roll amplitude
error dropped from **2.7x over-prediction in sideslip and 4.8x in yaw rate** (10.6° and 21.9 °/s, against 3.9°
and 4.6 °/s measured) to **within 10%**, tracking the measured traces in phase across the full 20-second record.

Runs in real time on a fixed-step `ode4` solver at 50 Hz with live FlightGear visualization and RC transmitter
stick inputs for pilot-in-the-loop handling-qualities assessment. Trim across airspeed, flight-path-angle and
bank-angle constraints; linearization to state space; short-period, phugoid, Dutch roll and spiral eigenvalues
with damping ratios and natural frequencies.

### [bumperbot_ws — Modular C++ Autonomy Stack](https://github.com/rohitsanjay-17-aerohub/bumperbot_ws)
> *C++ · ROS 2 · Nav2 Plugin Architecture · Kalman Filtering · Behavior Trees*

A 13-package ROS 2 workspace where **every planner and controller is written from scratch in C++ as a
`pluginlib` plugin against an abstract Nav2 base class** — A* and Dijkstra as `nav2_core::GlobalPlanner`,
pure pursuit and PD path-following as `nav2_core::Controller`. Swapping algorithms is a one-line config change,
no rebuild.

Also includes a Kalman filter in C++, log-odds occupancy-grid mapping, a `ros2_control` hardware interface with
serial transport, `robot_localization` EKF and AMCL configuration, and behavior trees for navigation with
replanning and recovery.

[Watch the Nav2 demo](https://drive.google.com/file/d/1vR_AhagI9RF4NhfAt_DB1W1sXTq92bfy/view?usp=sharing)

> Built while working through Antonio Brandi's ROS 2 course material; the planner, controller, filter and mapping
> implementations are written out in C++ and extended here as a study of plugin-based architecture.
> Repo excludes the AWS RoboMaker Gazebo world assets (since archived by AWS) — equivalent world files are at
> [Automatic Addison's collection](https://automaticaddison.com/useful-world-files-for-gazebo-and-ros-2-simulations/).

### Multi-UAV Safe Control — GCBF+ on Crazyflie Dynamics *(Safe Robotics Group, ASU)*
> *JAX · Graph Neural Networks · Control Barrier Functions · ROS 2 · Repo coming soon*

Reproduced published Neural Graph Control Barrier Function (GCBF+) results on Crazyflie quadrotor dynamics,
retraining the graph neural network from scratch on ASU's SOL A100 GPU supercomputer after a JAX API break and
an XLA compilation fault on newer hardware. Reached **100% safety at zero cost for 4, 8 and 16 agents**, against
91.7% safety and 0.67 cost for the nominal controller, with inference benchmarked at roughly 6 ms for 16 agents
inside a 50 Hz real-time budget.

Authored a three-experiment evaluation suite (position swap, scalability sweep, controller comparison) and
packaged the stack as a ROS 2 `ament_python` package with a four-drone deployment configuration. Hardware
integration on physical Crazyflie 2.1 units with Lighthouse v2 positioning is in progress.

### [Field-Oriented Control of an IPMSM — Electric Actuator Model](https://github.com/rohitsanjay-17-aerohub/FOC_PMSM)
> *MATLAB/Simulink · Motor Control · Actuator Modeling*

Field-oriented control of an interior permanent-magnet synchronous motor: an outer PI speed loop commanding
quadrature-axis current, inner d–q current regulators producing voltage references, and inverse Park/Clarke
transforms back to three-phase drive. Built as a **reusable electric actuator model** for the control-surface
servos and propulsion in larger vehicle and flight simulations, where actuator time constants shape the
closed-loop response of the whole system.

### MPC Regenerative Braking & Lyapunov Yaw Control *(EGR 560, Team Lead of 3)*
> *MATLAB/Simulink · MPC Toolbox · CarSim Co-Simulation · Repo coming soon*

Derived nonlinear longitudinal EV dynamics (aerodynamic drag, rolling resistance, road grade), linearized about
18.5 m/s and discretized zero-order-hold to state space, then designed a constrained QP model-predictive
controller with road-slope preview: roughly **30% improvement in battery state of charge** and ±0.5 m/s speed
tracking against ±2 m/s for a reactive baseline.

Separately implemented a Lyapunov-based direct yaw-moment controller on a bicycle lateral model, verified by
CarSim/Simulink co-simulation of a 120 km/h double lane change on a low-friction surface.
